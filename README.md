# @usteam/contracts

Общий пакет protobuf-контрактов платформы. Единственный источник истины для всех gRPC-взаимодействий между сервисами, плюс TS-интерфейсы асинхронных событий RabbitMQ.

## Установка

```bash
npm install @usteam/contracts
```

## Локальная разработка

```bash
npm install
npm run generate   # protoc + ts-proto → gen/ts. Требует установленного protoc в системе.
npm run build       # tsc -p tsconfig.build.json → dist/
```

⚠️ `gen/ts` пуст в репозитории (генерируется на этапе публикации). Любая попытка использовать пакет локально до `npm run generate` не будет содержать актуальных TS-типов для gRPC-клиентов/серверов.

Для Go-части (используется только `media-service`):
```bash
./scripts/generate_go.sh
```

## Структура

- `proto/*.proto` — контракты всех сервисов, единственный источник истины
- `src/proto/paths.ts` — `PROTO_PATHS`, абсолютные пути к `.proto`-файлам (для сервисов, строящих gRPC-клиент вручную через `@grpc/proto-loader`)
- `src/events/*` — TS-интерфейсы событий RabbitMQ (`auth-service` → `notification-service`)
- `gen/ts` — сгенерированные TS/NestJS-типы (генерируются при публикации, не хранятся в git)
- `gen/go/media` — сгенерированные Go-типы для `media.proto` (единственный Go-сервис платформы)

## Добавление нового gRPC-контракта

1. Создать `.proto`-файл в `proto/`, следуя стилю существующих файлов (см. `arena.proto` как образец CRUD + список + получение по id).
2. Добавить путь в `PROTO_PATHS` (`src/proto/paths.ts`).
3. Если контракт будет использоваться через `@usteam/common`'s `GrpcModule.register(...)`, также нужно зарегистрировать пакет в реестре `GRPC_CLIENTS` пакета `@usteam/common` (`lib/grpc/registry/grpc.registry.ts`) — это отдельный npm-пакет, правки в нём делаются отдельно.
4. Поднять версию пакета (`package.json`).

## Публикация

Публикация в npm и генерация/публикация Go-модуля происходят автоматически через GitHub Actions при пуше в `main` (`.github/workflows/publish-npm.yml`, `.github/workflows/publish-go.yml`).

## Важно

- Переименование существующих `message`/`rpc` в `.proto`-файлах меняет имена сгенерированных TS-типов — такие правки нужно синхронизировать со всеми потребителями контракта одновременно (искать использование по имени типа во всех сервисах).
- Изменение порядковых номеров полей или значений `enum` — breaking change на уровне wire-формата, а не только типов; никогда не переиспользуйте и не переставляйте существующие номера, только добавляйте новые в конец.
